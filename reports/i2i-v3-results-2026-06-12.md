## 2. 🔍 mmx i2i 真实能力（GitHub 调研）

### 2.1 关键发现：mmx 1.0.16 的 i2i 入口

来源：[`MiniMax-AI/cli` GitHub `src/commands/image/generate.ts`](https://github.com/MiniMax-AI/cli)

```typescript
// mmx CLI v1.0.16 源码关键逻辑
if (flags.subjectRef) {
  const refStr = flags.subjectRef as string;
  const params = Object.fromEntries(
    refStr.split(',').map(p => {
      const eqIdx = p.indexOf('=');
      return [p.slice(0, eqIdx), p.slice(eqIdx + 1)];
    })
  );

  const ref: { type: string; image_url?: string; image_file?: string } = {
    type: params.type || 'character',
  };

  if (params.image) {
    if (params.image.startsWith('http')) {
      ref.image_url = params.image;
    } else {
      // 本地路径自动转 base64 data URI
      ref.image_file = localFileToDataUri(resolve(params.image));
    }
  }

  body.subject_reference = [ref];
}
```

**关键事实**：
1. `--subject-ref` 接受 `type=character,image=<local_path_or_url>` 格式
2. **本地路径自动转 base64 data URI**（无需 upload 到 CDN）
3. `type` 字段在 CLI 层是任意 string，但 **API 服务端只接受 `character`**
4. ⚠️ `mmx file upload` 命令在 v1.0.16 暴露但 **endpoint 404**（file storage 接口未实装）

### 2.2 通过的 API 调用格式

```bash
mmx image generate \
  --prompt "..." \
  --aspect-ratio 16:9 \
  --n 4 \
  --subject-ref "type=character,image=<local_path>" \
  --out-dir ./output
```

### 2.3 失败的尝试

```bash
# ❌ 失败: type=image
mmx image generate --subject-ref "type=image,image=..."
# API error: subject_reference must be character

# ❌ 失败: file upload
mmx file upload --file ./sketch.jpg
# API error: HTTP 404
```

**结论**：当前唯一可用的 i2i 路径是 `type=character + 本地路径`。

## 3. 🆚 纯 t2i vs i2i+t2i 对比

### 3.1 纯 t2i (V3 final, via54 img)

```bash
via54 img --scene "<V3 prompt 1497 chars>" --platform minimax --ar 16:9 --n 4 --prefix strict-v3
```

### 3.2 i2i + t2i (mmx 直跑)

```bash
/usr/local/bin/mmx image generate \
  --prompt "<V3 prompt 1497 chars>" \
  --aspect-ratio 16:9 \
  --n 4 \
  --subject-ref "type=character,image=<sketch.jpg>" \
  --out-dir ./output
```

### 3.3 关键技术差异

| 维度 | 纯 t2i (via54) | i2i + t2i (mmx) |
|------|----------------|----------------|
| 草图参考 | ❌ 没有 | ✅ 草图作 subject_reference |
| 角色一致性 | 弱（AI 自由发挥）| 强（草图锚定角色）|
| 色调传染 | 无 | 有（草图色调影响输出）|
| 构图保留 | 0%（AI 自由生成）| 部分（草图布局部分保留）|
| 调用复杂度 | 简单（via54 img 一行）| 中等（绕过 via54 直接调 mmx）|

## 5. 🔬 i2i 强度的精确分析

### 5.1 i2i 自动决定强度

mmx **没有 `--strength` / `--denoise` flag**（i2i 强度参数）。AI 根据 prompt 和草图自动决定保留比例。

观察 4 张图：
- **角色身份**：保留 100%（同亚洲女性五官）
- **头发**：保留 100%（同款短发）
- **配饰**：保留 100%（耳钉+项链）
- **表情对比**：保留 50-70%（原图焦虑 vs 微笑差异被弱化，4 张里 003/004 两人表情都偏中性）
- **构图（左右对称）**：保留 80%
- **色调**：完全按 prompt 改写（草图灰底 → 蓝底）
- **文字**：按 prompt 移除（草图中央中文 → 中央留白）

### 5.2 关键工程发现

**i2i + prompt 的"分工"**：
- **草图控制**: 角色身份、发型、配饰、五官比例（强保留）
- **prompt 控制**: 风格（写实）、色调（蓝底）、背景（水珠）、构图细节（焦虑 vs 微笑）

**这就是为什么 i2i 显著优于纯 t2i**：草图锚定"是谁"，prompt 决定"做什么"。

## 6. 🛠️ 实战推荐方案（i2i + t2i 综合）

### 6.1 推荐命令模板

```bash
# 1. mmx 直接调用 (via54 不透传 --subject-ref)
cd /path/to/project

/usr/local/bin/mmx image generate \
  --prompt "<精确 prompt (1497 chars 限制)>" \
  --aspect-ratio 16:9 \
  --n 4 \
  --seed -1 \
  --subject-ref "type=character,image=<草图绝对路径>" \
  --out-dir ./output \
  --out-prefix i2i
```

### 6.2 prompt 工程要点

| 要素 | i2i 场景 | 纯 t2i 场景 |
|------|---------|-----------|
| 角色描述 | 简略（草图锚定）| 详细（AI 自由发挥）|
| 风格/色调 | 详细 | 详细 |
| 构图细节 | 简略（草图参考）| 详细 |
| 情感/表情 | 详细 | 详细 |
| 配饰 | 简略（草图参考）| 详细 |
| 整体长度 | ~1000 chars 足够 | 需要 1497 chars |

**i2i 场景下 prompt 可以更短**（草图承担 50% 信息），但 mmx API 仍有 1500 chars 限制。

### 6.3 何时用 i2i，何时用纯 t2i

| 场景 | 推荐 | 原因 |
|------|------|------|
| 草图 → 成品（保留角色）| **i2i** | i2i 锁角色，prompt 改风格 |
| 概念 → 草图（无参考）| 纯 t2i | i2i 没有参考图 |
| 角色一致性多张图 | **i2i** | i2i 锁角色，比 t2i prompt 描述稳定 |
| 完全自由的创意 | 纯 t2i | i2i 受草图限制反而束缚 |
